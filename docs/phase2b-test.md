# 第 2b 阶段测试说明：码率自适应、HEVC、硬件解码、远程光标

编译方式和第 2a 阶段一样，没有新的 vcpkg 依赖。查看器新增 `vncviewer/VideoCursor.*`，并链接 `d3d11`（源文件里已有 `#pragma comment`）。

## 1. 看日志确认用的是哪种方式

查看器日志（`-loglevel 10 -logfile ...`）开启视频模式时会有：

```
video: requested, HEVC                      ← 或 H.264（本机能用显卡解码 HEVC 才请求 HEVC）
video: stream 1: 1920x1080 at 0,0, HEVC, GPU decoding
```

最后一项是 `GPU decoding` 还是 `software decoding`，以及实际格式（服务端显卡不支持 HEVC 时会退回 H.264）。如果 GPU 解码出了问题，会看到 `GPU decoding failed, switched to software decoding`。

服务端调试日志每 10 秒一行：

```
video: sent 600 frames (25000 KB), skipped 0 in the last 10 s, 18000 kbps, rtt 12 ms
```

码率变化时（调试级别）：`video: congestion: 20000 -> 14000 kbps` / `video: probing: 14000 -> 15000 kbps`。

## 2. 测试用例

### 硬件解码和 HEVC

| # | 操作 | 预期 |
|---|---|---|
| 1 | 查看器机器装有「HEVC 视频扩展」，显卡较新，开启视频模式 | 日志 `HEVC, GPU decoding`；画面正常 |
| 2 | 查看器没装 HEVC 扩展 | 日志 `H.264, GPU decoding` |
| 3 | 服务端显卡太老不支持 HEVC 编码（GTX 9 系以前），查看器请求 HEVC | 服务端日志 `HEVC not available ..., using H.264`；查看器日志里格式是 H.264；画面正常 |
| 4 | 对比开启视频模式时查看器的 CPU 占用，与第 2a 阶段相比 | 明显下降（GPU 解码） |
| 5 | 4K 显示器开启视频模式 | 流畅；查看器 CPU 占用可以接受 |

### 远程光标

| # | 操作 | 预期 |
|---|---|---|
| 6 | 视频模式下把鼠标移到远程的文本框上 | 光标变成 I 形；在白底上是黑色的（反色） |
| 7 | 移到窗口边缘、链接上 | 双向箭头、手形等，和远程一致 |
| 8 | 运行一个会隐藏鼠标的程序（全屏视频播放器静止几秒，或游戏） | 查看器里也不显示光标 |
| 9 | 关闭视频模式 | 立刻恢复成原来的本地光标（点或箭头，按查看器设置） |

### 码率自适应（需要限速工具，例如 clumsy 或 NetLimiter）

| # | 操作 | 预期 |
|---|---|---|
| 10 | 不限速，播放视频 | 码率在几秒内升到 20000 kbps 左右，`skipped 0` |
| 11 | 限速 5 Mbps，播放视频 | 码率降到 5000 以下并稳定；画面变糊但流畅、延迟不持续变大；打字到屏幕出现字的延迟基本不变 |
| 12 | 限速中途取消限速 | 码率在十几秒内逐步回升 |
| 13 | 加 100 ms 延迟、1% 丢包 | 能用；画面偶尔卡一下但不会越来越慢 |
