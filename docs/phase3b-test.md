# 第 3b 阶段测试说明：单窗口 + 视频模式

## 1. 编译

新增 `common/RateController.*`（码率自适应，从推流代码里抽出来的共用模块），已加入服务端的 Visual Studio 工程和 CMake。没有新的依赖。

单元测试：`tests/rate_controller`（Linux 下 `run.sh`，或 `cl /std:c++17 /EHsc tests\rate_controller\rate_controller_test.cpp common\RateController.cpp`）。`tests/window_e2e` 新增了视频传输方式的用例，我在 Wine 里跑过，全部通过。

## 2. 使用

两个菜单项可以组合使用：

| 先做 | 再做 | 结果 |
|---|---|---|
| 打开 Video Mode | 选 Single Window | 这个窗口用显卡视频编码传输 |
| 选 Single Window | 打开 Video Mode | 当前窗口从无损分块切换成视频 |
| 单窗口 + 视频 | 关掉 Video Mode | 当前窗口切回无损分块 |
| 单窗口 + 视频 | 关掉 Single Window | 回到整个显示器的视频流 |

## 3. 看日志

服务端：
```
window: sending the window as video                  ← 或 video not available, sending lossless tiles
video: window video 1280x720, 10000 kbps, H.264
```
查看器：`video: stream N: 1280x720 at 0,0, ...`（位置固定是 0,0）。

## 4. 测试用例

| # | 操作 | 预期 |
|---|---|---|
| 1 | 打开视频模式，再选一个**正在播放视频的播放器窗口** | 只显示这个窗口，播放流畅；日志有 `sending the window as video` |
| 2 | 选一个浏览器窗口（单窗口模式，分块），再打开视频模式 | 画面切换成视频，内容连续；滚动网页流畅 |
| 3 | 接着关掉视频模式 | 切回无损分块，文字清晰 |
| 4 | 单窗口 + 视频时，关掉单窗口模式 | 回到整个显示器的视频画面 |
| 5 | 单窗口 + 视频时，远程调整窗口大小、打开对话框 | 查看器画面跟着变大变小，内容正确（会有约一帧的闪烁，这是重开编码器） |
| 6 | 单窗口 + 视频时，窗口内容静止 | 几乎没有网络流量 |
| 7 | 单窗口 + 视频时，最小化 / 关闭远程窗口 | 和单窗口分块模式一样：询问还原 / 回到桌面 |
| 8 | 服务端**没有 NVIDIA 显卡**时，开视频模式（会提示不支持），然后选单窗口 | 单窗口以分块方式正常工作 |
| 9 | 单窗口 + 视频时限速 5 Mbps | 码率自动降下来，画面流畅、延迟不持续变大 |
| 10 | 鼠标、键盘、弹出菜单 | 和 3a 一样（输入路径没有变） |

## 5. 码率控制的一个修正（第 2 阶段视频模式也受益）

以前：网络延迟永久性变高（比如换了网络）后，码率会一直卡在最低值。现在最多 30 秒后会适应新的延迟水平，码率重新回升。如果你有条件，可以用限速工具先加 200 ms 延迟、保持一分钟，看服务端日志里的码率是否回升。
