# 第 6 阶段测试说明：文件浏览模式 + 新的文件传输窗口

设计见 `docs/design.md` 第 6 节。第 5 阶段（AV1）还没测的话，可以一起测，说明在 `docs/phase5-test.md`。

## 1. 编译

新增文件，已经加入 Visual Studio 工程和 CMake：

| 位置 | 文件 |
|---|---|
| 公共 | `common/FileManProto.*`（协议、路径检查）、`common/FileManServer.*`（服务端引擎，查看器也用到其中的字符串 / 时间小函数）、`common/FileManClient.*`、`common/FileTransferQueue.*` |
| 服务端 | 只改了 `vncExtChannel.*`（打开 channel 5） |
| 查看器 | `FileManagerWindow.*`、`FileManagerDragDrop.*`、`ClientConnectionFiles.cpp`；改了 `ClientConnection.*`、`ClientConnectionExt.*`、`SessionDialog.cpp`、`VNCOptions.*`、`res/resource.h`、`res/vncviewer.rc` 和各个语言的 `translations/vncviewer/*/vncviewer.rc`（连接对话框加了一个勾选框） |

没有新的 vcpkg 依赖。新用到的系统库：shell32、ole32、uuid（CMake 里加了；MSVC 用 `#pragma comment` 自动链接）。

单元测试（我在 Linux 下用 MinGW + Wine 跑过，都通过了）：
- `tests/fileman_proto`：协议编解码、截断消息、路径检查（`..`、设备名、非法字符、`\\?\` 前缀等）。
- `tests/fileman_e2e`：服务端 + 客户端 + 队列整套跑，路径里带中文。覆盖：
  - 列目录（包括 2500 个文件的分页）、新建、改名、递归删除（里面有只读文件）。
  - 3 MB 文件上传 / 下载，内容逐字节一致，修改时间保留。
  - 0 字节文件。
  - 已存在时不覆盖 / 覆盖。
  - 中途取消、中途断线：不留下半个文件或临时文件。
  - 队列：文件夹上传 / 下载，冲突时的跳过 / 两个都保留 / 全部替换，取消排队中的项目。
- `tests/fileman_window`：在 Wine 里打开窗口，选文件、点上传、截图。用来检查界面代码能跑，不检查好不好看（Wine 没有 Segoe UI 和图标字体，按钮上的图标显示成方框）。

在 Windows 上也可以直接跑 e2e 测试：
```
cl /std:c++17 /EHsc /I. tests\fileman_e2e\fileman_e2e_test.cpp common\FileManProto.cpp common\FileManServer.cpp common\FileManClient.cpp common\FileTransferQueue.cpp common\ExtChannel.cpp
fileman_e2e_test.exe
```

## 2. 使用

- **文件浏览模式**：连接对话框里勾选「File transfer only」（中文界面是「仅文件传输」），或者命令行：
  ```
  vncviewer.exe 192.168.1.10 /filemode
  ```
  连上后只出现文件传输窗口；关掉它就断开连接。
- **普通连接**：系统菜单 / 工具栏的 File Transfer 打开的就是新窗口（连原版服务端时还是原版窗口）。

## 4. 测试用例

### 文件浏览模式
| # | 操作 | 预期 |
|---|---|---|
| 1 | 勾选「仅文件传输」连接 | 输入密码后只出现文件窗口，在最前面；没有远程桌面窗口（任何途径都不会把它显示出来）；任务栏上只有文件窗口；不会向远程发送任何键盘鼠标操作；服务端几乎没有画面流量 |
| 2 | 关掉文件窗口 | 连接断开，查看器退出（不弹「确定退出吗」） |
| 3 | 命令行 `/filemode` | 同 1 |
| 4 | 服务端关掉 File Transfer 权限后用文件浏览模式连接 | 提示「服务端不允许文件传输」，然后断开 |
| 5 | 文件浏览模式连**原版** UltraVNC 服务端 | 约 5 秒后打开原版文件传输窗口；关掉后断开 |
| 6 | 文件浏览模式下拔网线几秒再插上（开着自动重连） | 右边显示 Not connected；重连后回到原来的文件夹 |
| 6a | 服务方式运行、**没人登录**、「User impersonation (for Service only)」勾选（默认） | 弹出提示：没有用户登录，以及要改哪个设置；右边状态栏显示同样的原因 |
| 6b | 同上，但取消勾选这个设置（立即生效，在窗口里按 F5 刷新） | 能浏览和传文件；常用文件夹里有「Users」（`C:\Users`）；服务端日志有 `file manager: nobody is logged on, file access as the service` |
| 6c | 6b 之后有人登录 Windows，在窗口里按 F5 | 下拉框里出现这个用户的桌面 / 文档 / 下载，之后的文件操作以这个用户的身份进行 |
| 6d | 通过远程桌面登录远程机器（VNC 看到的是登录界面），用文件浏览模式连接 | 以远程桌面里那个用户的身份访问文件（下拉框里有他的桌面 / 文档 / 下载）；服务端日志有 `desktop user token: using the user of session N` |

### 窗口
| # | 操作 | 预期 |
|---|---|---|
| 7 | 打开窗口 | 左边是上次的本机文件夹（第一次是「文档」），右边是这台服务器上次的文件夹（第一次是远程桌面） |
| 8 | 下拉框选盘符 / 桌面；地址栏输入路径回车；输入 `%TEMP%` 回车 | 都能跳过去；输错的路径给出原因并留在原处 |
| 9 | 双击文件夹、`..`、Backspace、Alt+↑ | 进入 / 返回上一级，返回后选中刚才所在的文件夹 |
| 10 | 点列头 | 排序，文件夹总在前面；名称按自然顺序（file2 在 file10 前） |
| 11 | F7 新建文件夹（两边都试） | 建好后直接进入改名状态 |
| 12 | F2 改名；改成带 `?` 或以点结尾的名字 | 正常改名；非法名字给出提示 |
| 13 | Del 删除（本机） | 确认后进回收站 |
| 14 | Del 删除（远程，含子文件夹） | 提示「不可恢复」，确认后删除 |
| 15 | 选几个文件和一个文件夹，点「Upload →」 | 队列里每项显示进度条、速度、剩余时间；完成后右边自动刷新并选中 |
| 16 | 「← Download」一个大文件夹（几千个小文件） | 先显示 Scanning…，然后逐个文件传，状态里显示当前文件名 |
| 17 | 拖动：左→右、右→左、拖到某个文件夹上 | 传到当前文件夹 / 那个文件夹（拖过去时文件夹高亮） |
| 18 | 从资源管理器拖文件到右边 | 上传 |
| 19 | 从左边拖文件到资源管理器 | 本机复制（就是普通的文件拖放） |
| 20 | 传一个对方已经有的文件 | 弹出：替换 / 跳过 / 两个都保留，显示两边的大小和时间；勾选「对剩下的都这样做」后不再问 |
| 21 | 传输中点 Cancel（或在队列里按 Del） | 停止；目标位置没有半个文件，也没有 `~uvnc-*.part` 临时文件 |
| 22 | 传输中断开连接 | 当前项目标记失败，原因是 disconnected；目标位置没有半个文件 |
| 23 | 传一个 >4 GB 的文件 | 正常，速度稳定 |
| 24 | 路径超过 260 个字符的文件 | 能列出、能传 |
| 25 | 文件名带中文、emoji | 正常 |
| 26 | 传输中关窗口 | 先问「还有传输在进行，要停止并关闭吗」 |
| 27 | 把窗口移到另一个缩放比例不同的显示器 | 字体和布局跟着变，不模糊 |
| 28 | 关掉再打开窗口 | 大小、位置、分割比例、文件夹都记住了 |
| 29 | 传大文件时在远程桌面上操作（普通连接） | 画面不卡（文件数据优先级最低） |
| 30 | 传大文件的同时在另一边浏览文件夹 | 列目录不用等传输结束 |

## 5. 已知限制

- 还不能从远程一侧直接拖到资源管理器（只能拖到左边）。
- 没有断点续传：断线后要重新传整个文件。
- 界面文字是英文。
- 查看器以管理员身份运行时，Windows 不允许从普通权限的资源管理器拖进来；窗口内左右拖动不受影响。
